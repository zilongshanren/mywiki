# 一个内存碎片度量公式

Adam Sawicki 在维护 [[vulkan-memory-allocation]] 与 [[d3d12-memory-allocator]] 的过程中，给"内存碎片程度"提出了一个朴素但好用的度量公式。核心只有一条：取所有空闲区间大小的平方和再开方，对总空闲量归一化，用 `1 - 该值²` 作为碎片度。

## 想要的性质

一个好的碎片度量，Adam 认为应该满足：

- 归一化到 `[0, 1]`。
- 与单位无关（字节、MB 结果一致）。
- **和碎片总量无关**——这是另一个独立量，不该掺进来。
- **和分配个数无关**——一大块和紧挨着的多小块应等价。
- 单一连续空闲区间 → 0；空闲被均匀分成多份 → 尽量接近 1。

## 为什么简单方案都不够

- **"只看最大空闲区"**：`1 - LargestFree / TotalFree`。会忽略除了最大空闲外的所有结构，`|##|##|##|........|##|` 和 `|##|..|##|..|##|..|##|` 给一样的分——显然不合理。
- **"数空闲段个数"**：`(FreeRegionCount - 1) / AllocationCount`。它依赖分配数量；而且任何一个小洞都会显著抬高指数，即使旁边还有大片连续空闲。

## 平方-开方公式

给定空闲区间大小数组 `f[0..n-1]`：

```text
Quality        = Σ f[i]²
QualityPercent = sqrt(Quality) / Σ f[i]
F              = 1 - QualityPercent²
```

直觉：`sqrt(Σx²) / Σx` 是 L2 / L1 范数比——越集中（一个大块）越接近 1，越均分越接近 `1/√n`。再用 `1 - x²` 把"质量"翻成"碎片度"。

## 数值行为

- `[1000]` → `F = 0`
- `[500, 500]` → `F = 0.5`
- `[1]*20` → `F = 0.95`
- `[200, 800]` → `F = 0.32`
- `[200, 800, 1, 1, 1, 1]` → `F = 0.3254`（一堆小洞不会淹没主结构）

n 个等大空闲段给 `F = (n-1)/n`，永远差一点到 1——Adam 说这算个瑕疵，但无伤大雅。

## 适用范围与局限

这个公式针对**单块内存**的碎片度。跨块（allocator 管理多个 heap）是另一种问题：跨块时更重要的是找出"几乎为空的块"并把它搬空还给系统，而不是测某块的碎片度——所以这套 metric 只能是整体策略的一环。

Adam 说他后来 google 发现 `rhempel/umm_malloc` 早有人提过同样公式，算是独立再发明。
