# Tesla Dojo 微架构

Tesla Dojo 是 Tesla 为内部机器学习训练任务自研的专用处理器架构，于 2022 年 Hot Chips 34 大会上公开。与购买 AMD/Intel/Nvidia 的现成产品不同，Tesla 选择设计自有微架构，以便在自身的训练工作负载上作出普通架构无法实现的权衡。

## 高层设计目标

Dojo 是一个 8-wide、4-way SMT 的核，运行在保守的 2 GHz。它拥有类 CPU 的流水线，比 GPU 更能应对分支密集的代码和不规则访问模式。但为了最大化计算密度，Dojo 放弃了现代 CPU 的大量特性——在某些方面更接近 IBM Cell 的 SPE（协处理元素）而非通用处理器。

## 前端与分支预测

Dojo 有一个基本的分支预测器（含 BTB），每周期从"小型"指令缓存拉取 32 字节。指令缓存不具备一致性（incoherent）——若新代码被 DMA 加载到本地 SRAM，必须先刷新指令缓存再跳转执行。解码器每周期处理 8 条指令（来自 2 个线程），部分指令（分支、谓词操作、立即数加载）可在前端直接执行并丢弃出流水线，无需进入后端，这类似于 x86 CPU 的寄存器移动消除，但 Dojo 不做精确异常（precise exceptions）——不跟踪指令退休以维持顺序提交。

## 执行引擎

整数侧仅 4-wide，2 个 ALU + 2 个 AGU，目的是提供足够的控制流和地址生成能力以喂饱向量单元，而非最大化整数吞吐。真正的计算重心在向量和矩阵侧：一条管道做 512-bit 向量执行，另一条做 8×8×4 矩阵乘法。354 核 Dojo die 在 2 GHz 下可达 362 BF16 TFLOPS，即每核每周期 512 BF16 FLOP。

Dojo 似乎支持一定程度的乱序执行——整数侧可以跑在向量侧大幅前面，直到调度队列填满。但由于无精确异常，不需要大型 ROB 来维护顺序提交状态，节省了面积和功耗。

## 本地 SRAM 而非缓存

Dojo 核无法直接访问系统内存，而是通过 1.25 MB 的本地 SRAM 作为主要数据存储。这块 SRAM **不是缓存**——它由软件直接管理，通过 DMA 操作将系统内存数据搬入。SRAM 拥有 5 个 512-bit 端口（2 个 load、1 个 store、2 个连接 mesh）。

因为不需要标签和状态位，SRAM 延迟可以做到接近 L1 缓存水平（类比去掉缓存 tag lookup 的 L2，约可减少 3 个流水级）。但代价是程序员必须手动管理数据局部性。

无虚拟内存支持意味着没有 TLB、没有页表遍历、没有分页到磁盘，SMT 的 4 个线程更多是为了单一应用在计算和 DMA 数据加载之间重叠（而不是多任务）。

## 物理实现与部署形式

单个 Dojo D1 die 面积 645 mm²，不含 DDR/PCIe 控制器——这些全部省掉，换来的是更高的核心密度：28.9% 的 die 面积用于 SRAM 和核以外的逻辑（对比 AMD Zeppelin 的 44%）。Die 边缘为定制高速 IO，专门设计用于与相邻 die 互联（延迟约 100 ns）。

最小可用部署单元包括一个 D1 die、一个携带 HBM 的 interface processor 卡（提供 DRAM 访问）和一个 host 系统。实际部署以 25 die 为一个 tile，160 GB HBM，4.5 TB/s 链路带宽。

## 与 IBM Cell SPE 的对比

| 特征 | Tesla Dojo | IBM Cell SPE |
|------|-----------|-------------|
| 本地存储 | 1.25 MB SRAM，5 个 512-bit 端口 | 256 KB，单端口 128 B/cycle |
| 时钟 | 2 GHz（保守）| ~3.2 GHz（激进深流水）|
| 核宽度 | 8-wide（低频宽度优先）| narrow（高频深度优先）|
| Host 位置 | 独立 host 系统（PCIe 卡）| 同一 die（PPE）|
| 设计目标 | ML 训练超算 | 多媒体/游戏 |

## 设计哲学的启示

Dojo 展示了一种极端的"为特定工作负载剪裁"路线：牺牲通用性（精确异常、虚拟内存、多任务、跨 die 缓存一致性），换取极高的计算密度和能效。随着进程节点改进放缓，专用硬件（如 Dojo）成为延续计算能力增长的主要手段之一。
