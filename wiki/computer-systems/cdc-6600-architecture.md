# CDC 6600 架构

CDC 6600 是 Control Data Corporation 于 1964 年推出的大型机，由 Seymour Cray 主导设计，是当时世界上最快的计算机。它以极简主义的硬件哲学实现了惊人的吞吐量，并引入了若干至今仍被教科书引用的微架构概念。

## 整体架构

中央处理器（CP）是 60 位标量顺序执行核，运行在 10 MHz——与 Central Memory 同频。这一设计的关键优势在于无需缓存：CPU 和内存速度匹配，直接访问即可。指令集精简，不足 100 条，全部硬件直接执行，无需微码翻译（这在 1960 年代颇为罕见）。

寄存器文件共 24 个：8 个 60 位操作数寄存器（X0-X7）、8 个 18 位地址寄存器（A0-A7）、8 个 18 位增量寄存器（B0-B7）。写入限制有意设计以简化布线——只有 X0-X5 可承接 Memory Load，X6/X7 才能写回 Memory。

## 功能单元与并行执行

CDC 6600 的核心性能来自 10 个独立非流水化功能单元，理论上可全部同时运行：

- 增量单元 ×2（用于地址计算）
- 布尔逻辑单元 ×1
- 移位单元 ×1
- 整数加法单元 ×1
- 整数减法单元 ×1
- FP 加法单元 ×1
- FP 乘法单元 ×2
- 除法单元 ×1

FP 乘法单元的复制使得流水线"接力"成为可能：一条 FP 乘法指令仍在执行时，第二条可以发射到另一个乘法单元。10 周期的 FP 乘法延迟是当时的硬件代价，需要程序员精心排布指令混合才能充分利用吞吐量。

## Scoreboard 调度

依赖管理由 [[scoreboard-scheduling]] 机制负责。Scoreboard（计分板）跟踪每个功能单元是否忙碌，以及哪些寄存器正在等待写回。满足以下条件后指令才能发射：目标功能单元空闲；所有源寄存器已就绪（无 RAW 冒险）；无 WAW 冒险。

由于没有寄存器重命名，CDC 6600 也需处理 WAR（写后读）冒险：每次回写都需检查所有待读寄存器。这是 Tomasulo 算法（1967 年，IBM）出现之前的解决方案，Tomasulo 通过寄存器重命名彻底消除了 WAR 和 WAW 冒险。

## 内存子系统

Central Memory 最大 960 KB，分为 32 个 bank（每 bank 4096 字），由低位地址选 bank。理想情况下 CP 可每周期读一个 60 位字（75 MB/s）。Bank 冲突检测不做地址比较，而是用超时机制：若目标 bank 在 175 ns 内未接受请求，则假设冲突并进入 300 ns 重试循环。这是一个以简单性换取偶发低效的取舍——与现代 CPU 对精确性的执念形成鲜明对比。

内存保护采用分段而非分页：每个进程有 Reference Address（基址）和 Field Length（长度），越界直接停机，不提供精确异常恢复。

## Extended Core Storage（ECS）

ECS 可选配件最大 14 MB（200 万个 60 位字），以 488 位行为单位存储，运行在 312.5 KHz。每次读写可在同一周期并行进行。ECS 提供 5K 字的备用存储，支持人工切换线路完成容错替换——比现代 ECC 粗暴，但可靠。

## 历史意义

CDC 6600 是"超级计算机"这一类别的奠基者。Seymour Cray 后来离开 CDC 创立了 Cray Research，继续以极简主义追求峰值性能。其设计原则——直接执行、无投机、无缓存、高带宽内存——与现代乱序超标量截然相反，但在晶体管稀缺的年代正是最优解。现代 CPU 复杂性的增长，本质上是用更多晶体管换取更高效的指令级并行和延迟隐藏。
