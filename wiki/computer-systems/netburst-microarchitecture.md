# NetBurst 微架构

NetBurst 是 Intel 为 Pentium 4（2000 年起）设计的微架构，核心思路是：依靠极长流水线换取极高主频，以频率优势弥补较低的 IPC。这一赌注最终以失败告终，但 NetBurst 在 Intel 历史上留下了深刻印记——它既是失败的教训，也是后来 Sandy Bridge 成功的技术基石。

## 核心设计理念

NetBurst 与前任 P6 架构（Pentium III）在几乎所有模块上完全不同，是一次彻底的重设计。主要设计决策包括：

**超长流水线 + 高频策略**：Prescott（90nm）核心拥有 31 级流水线，旨在冲击 10 GHz 目标频率，但实际产品止步于约 3.8 GHz，频率预期严重落空。

**Trace Cache 替代 L1i**：以 12K 条目的追踪缓存取代传统 L1 指令缓存，缓存的是解码后的微操作序列而非指令字节。这样做避免了跳转指令对取指带宽的切割，也降低了解码延迟。现代 Intel/AMD/ARM 的微操作缓存（uop cache）正是由此演化而来。

**PRF 物理寄存器堆方案**：放弃 P6 的 ROB+RRF 方案，改用独立的物理寄存器堆（PRF）。这降低了退休阶段的数据搬移开销，为 ROB 与寄存器堆大小的独立调整提供了条件，并为后续的移位消除特性奠定了基础。

**超大乱序结构**：调度器、ROB 等乱序结构在当时极为庞大，直到 Nehalem（2008 年）才被追上。但这其中有隐情：NetBurst 在分支预测失误后不会取消已取指的错误操作，而是等到退休阶段才释放资源，因此乱序窗口里充斥着"僵尸"指令，结构必须足够大才能保证有效吞吐。

**双速整数 ALU**：两个整数 ALU 以两倍核心频率运行，理论上一个三发射核心每周期可完成四次整数操作，但实际上这是为了消化 Trace Cache 未命中、分支预测失误、缓存缺失重放等大量无效工作而被迫配置的。

## 主要缺陷

**Trace Cache 容量效率低下**：12K 条目 × 64-bit 微操作 ≈ 96 KB 的实际 SRAM，却只相当于 8-16 KB 的传统指令缓存命中率。同一条指令在不同跳转路径下被多次缓存，浪费严重。Trace Cache 未命中时退化为 1-wide 解码，吞吐量骤降。

**不消除预测失误的错误操作**：节省了取消逻辑，却迫使乱序结构承担大量无效追踪开销。

**缓存缺失重放**：L1D 缺失的 Load 会被反复调度执行直到数据到达，浪费执行单元资源；依赖该 Load 的指令也一并重放。

**存储转发惩罚灾难性**：不对齐存储转发最差情况可达 165 周期惩罚，而同期其他处理器通常只需数十周期。

**写穿透（Write-Through）L1D**：每次写入立即穿透到 L2，写带宽仅为读带宽的四分之一（约 4 字节/周期），严重拖累内存密集型写负载。

**TLB 缺失与内存控制器外置**：地址翻译通过前端总线（FSB）连接到北桥的内存控制器，增加了约 100ns 的内存访问延迟，与 AMD 的集成内存控制器相比劣势明显。

## 技术遗产

失败的 NetBurst 却为后继者铺好了路。Sandy Bridge（2011 年）的成功，正是建立在 NetBurst 时期积累的工程经验之上：

- **微操作缓存**：Sandy Bridge 重新引入 uop cache，但与传统 L1i + 宽解码器配合，避免了 Trace Cache 的容量浪费问题。Sandy Bridge 的 uop cache 在组相联结构和 6-uop 缓存行设计上与 Trace Cache 有明显的继承关系。
- **PRF 物理寄存器堆**
- **超线程（HyperThreading）**：NetBurst 时期调试和验证了 HT 的实现
- **分散化调度器**：NetBurst 使用了分散式调度器，Sandy Bridge 开始将这一思路系统化

正是因为 NetBurst 趟过了这些技术坑，Sandy Bridge 才能在一代内实现全面优势，随后多年横扫 AMD。

## 与同时代竞品的对比

| 指标 | Pentium EE 965 (NetBurst) | Athlon 64 X2 6000+ |
|------|---------------------------|---------------------|
| L1D 大小 | 16 KB | 64 KB |
| L1D 延迟 | 4 周期 | 3 周期 |
| 内存控制器 | 外置（北桥） | 集成 |
| 内存延迟 | ~90 ns | 更低 |
