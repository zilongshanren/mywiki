# Mod-first 的引擎演化模型

[[cloudwu|云风]] 从 *Factorio: Space Age* 总结出的一条引擎设计原则：**官方扩展内容本身就是一个 Mod，核心系统围绕 Mod API 而不是围绕游戏内容进化**。

## 现象

Space Age 看起来是一个 DLC，但它的实现形态"和一众玩家 Mod 地位并无太大区别"。核心团队给自己也只是 Mod 作者的身份，内容的增量通过 Mod API 往上堆；而 2.0 主要的工程投入不是新内容，而是**对核心系统的打磨与对 Mod API 的扩展**：

- 信号可以控制机器换配方（新增加的 Mod 钩子）；
- 机器多了"回收箱"格位来容纳换配方时的残留物；
- 流体系统去掉了官方的"智能"拦截，把空间让给 Mod 与玩家自己解决；
- 机器可以读出更多内部状态（爪子抓取物、锅炉温度、储存箱），都是把"游戏状态"暴露给 Mod 的接口。

## 为什么这种演化模型重要

**核心系统稳定、演化方向清晰**。开发者不必在核心里堆无尽的游戏内容，每加一个玩法就要动一次底；而是用 API 让新内容以 Mod 形式挂上去。核心只对"API 如何更强"负责。

**玩家社区成为内容引擎**。Space Age 本身只是一个数量级，而围绕它的玩家 Mod 将是另一个数量级。云风自己从 Space Exploration Mod 入坑异星工厂，就是这种生态的直接证据。

**官方与玩家 Mod 共用同一套机制**。这意味着 API 的每一次扩展都同时惠及官方和玩家，没有"内部特权"。这一点和 [[game-engine-vfs]] 的思路同源——资源以同样规则被打包、同样规则被发现，无论是官方还是 Mod。

## 对比：把玩法焊死在核心里

反面是把每个玩法都写进引擎核心：加新机制 = 改核心代码。长期看，核心越来越臃肿、迭代越来越慢、模组作者越来越难拓展。传统 MMO 引擎多年来的教训就是这样——这也是云风做 [[ant-engine|Ant]] 时想避开的模式，见 [[engine-evolution]]。
