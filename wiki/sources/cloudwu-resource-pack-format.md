# 网易资源包格式与下一代设想（云风 / blog.codingnow.com）

[[cloudwu]] 发表于 2010 年 8 月的设计笔记，回顾他 9 年前为网易《大话西游》系列设计的资源包 / 补丁包格式，并讨论新引擎里希望做出的改进。

## 摘要

最初的设计目标是：解析快、定位单文件快、补丁体积小、可承受频繁更新。早期格式把所有文件首尾相连、在末尾追加索引表；索引中只存文件名 hash，不存路径字符串，文件名清单在另一个不公开的 `index` 文件里——和暴雪 MPQ 同源。和大多数打包格式不同的是，网易包**允许包内"空洞"**：删除文件不前移数据、新增文件优先复用空洞。这是为了避免 WoW / SC2 那种"补丁下载几分钟、本地 patching 几十分钟"的玩家体验；本质是在资源包里搞了个粗粒度的内存分配器。补丁不是小文件集合，而是**整个资源包的二进制 diff**，因为包内布局相对稳定、局部修改对二进制的影响很小，对未压缩贴图与无缝大地图文件尤其有效。第二种更新通路是把待更新的文件单独打成另一份高优先级包、引擎读取时优先在该包里检索——这与 Quake / Doom 的 `.pak` 覆盖机制完全一致。

下一代设计上，云风希望加上**内置压缩**（按块压缩，类似 FAT 表管理大文件分块，保留随机访问能力，方便嵌套包）、**包内链接**（相同内容的文件去重为软链接，引擎能识别，相同资源只加载一次），以及更友好的**逐小文件 diff 补丁工作流**——补丁包里直接放每个小文件的 diff，由 `patch` 工具抽出旧文件、合并、再压缩空洞、与新内容拼接发布。

## 关键要点

- 索引只存文件名 hash → 解包困难、防止资产被反向
- 允许包内空洞 → 删除文件不搬运数据，避免补丁打包时间爆炸
- 补丁 = 整包二进制 diff，不是小文件集合
- 历史前提：磁盘 IO 慢 + 大话西游无缝大地图需要随机访问 + 未压缩资源
- 旁路覆盖包：与 Quake / Doom 同思路
- 新设计：FAT 风格分块 + 块级压缩 + 包内链接去重 + 嵌套包
- 文本资产格式让二进制 diff 失效，触发新的逐小文件 diff 流程
