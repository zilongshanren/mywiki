# 关于虚拟文件系统的一些新想法（云风 / blog.codingnow.com）

[[cloudwu|云风]] 发表于 2024 年 2 月 22 日的短文，记录他在重构 [[ant-engine|Ant Engine]] 编辑器过程中对核心模块 [[game-engine-vfs|VFS]] 的一次反思——他怀疑当初为 VFS 引入的"不变快照"假设其实是多余的。

## 摘要

VFS 是 Ant Engine 的核心模块之一，云风最初按"带版本控制的网络文件系统"思路来设计，把运行时的 VFS 视为 Merkle tree 形式的一个不变快照，这样整个快照可以用一个哈希代表，并方便通过网络同步。但为了实现编辑器的动态修改能力，他不得不给这套设计打补丁。重构编辑器时他开始反思：**"不变快照"真的必要吗？** 他给出一个替代方案：VFS 变成一个纯内存、可动态增删的树结构，不需要持久化。启动时根节点是空目录；运行时可以把任意 `path` 绑定到一个 `hash`——若中间目录不存在就立刻补齐，若叶子节点已存在就覆盖；每个 `hash` 的数据内容可以是内存块或本地文件（带时间戳），由于 `hash` 是内容的 SHA1，同一 hash 只需绑定一次。另有一个独立模块负责**递归扫描本地目录**并生成 hash 表——如果离线启动，就扫本地、把所有 hash 绑定好、再把根替换为计算出的 root hash 即可；如果连接文件服务器，就按需向服务器请求 path 的 hash 和 hash 对应的内容，并在本地 cache，这部分和原有实现相同。好处是：VFS 退化为一个**纯内存数据结构的管理者**，不再操心网络同步和本地文件系统的对应关系，这两件事被剥离到外部模块。

## 关键要点

- 原方案把 VFS 按 git 式 Merkle tree 设计成"不变快照"，但编辑器需要动态修改——反复打补丁让两种语义纠缠在一起。
- 新思路：**放弃不变性假设**，VFS 变成运行时可增删查改的内存树。
- 每个叶节点是一个 hash 值；同一 hash 的内容只需绑定一次（因为是 SHA1 内容寻址）。
- 本地目录扫描 / 网络同步这两件事被抽成独立模块，不再混入 VFS 模块本身——**职责划分的再次清洗**。
- 这次反思还没有落地——云风明确说短期内不会把工作重心放到重构 VFS 上，先记录下来。
