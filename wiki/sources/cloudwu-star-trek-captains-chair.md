# Star Trek: Captain's Chair 初体验与 LLM 规则幻觉（云风 / blog.codingnow.com）

[[cloudwu|云风]] 发表于 2026 年 3 月 1 日的桌游笔记，双线：一是对 Nigel Buckle / David Turczi 2025 年设计的 ST:CC 的深度拆解（BGG weight 4.06，卡牌构筑 + 引擎构建的合成），二是用它做题材记录了一次典型的 LLM 规则答疑失败。

## 摘要

ST:CC 被作者评为"玩过的所有卡牌构筑类桌游中机制、策略和局势变化最丰富的"。他把这归结于**丰富的卡组瘦身机制**（LOG 永久移除、deploy 到桌面、beam 到飞船 / 星球、回合末自由保留手牌、市场卡自选放入抽牌或弃牌堆），让玩家能动态控制卡组而非被抽牌手气绑架。活动牌组稳定在 20 张以内。初始卡组不是 Dominion 式的同质基础卡 + 少量特殊卡，而是**每组 10 张全部独立设计**，游戏自带 6 套风格迥异的初始牌，每组还配固定补充卡 + 高级补充卡，按"抽牌堆抽空"节奏触发升级，平衡了套路学习成本和重开新意。卡片一卡多用（从手打出 / 桌面激活各有能力，且每种使用方式多能力二选一），桌面位置极多（LOG 区、升级区、事件区、附着区等），玩起来"有工人分配游戏的感觉"。每个初始牌组自带长线任务（如 PICARD：3 张同盟 beam 到同一飞船 + 4 科技 4 影响力），强迫玩家做多回合规划。单人 vs bot 体验好于两人对战（后者 downtime 大）。

LLM 部分才是博客真正的技术观察。作者尝试用 Gemini 辅助学习 ST:CC 的规则，但游戏太新网上资料少，Gemini **表现得很懂、信誓旦旦，但大量规则细节是错的**。两个具体案例：(1) bot 被要求 log 一艘飞船时如何处理，Gemini 编造了"把同一地区所有外派部队收回"这条根本不存在的规则，让作者去查规则书特定不存在的章节，甚至杜撰引用了 BGG 论坛帖子内容——反复追问都自信满满；(2) 舰长面板 A/B 面选择差异，Gemini 在搜索了 BGG 论坛后，把论坛下方玩家反复强调的"B 面科技 / 军事 / 影响力导轨设计不同"这一关键信息忽略了，反倒编造了一堆"A 面让玩家更专注""完成难度不同"的错误解释。

作者的结论很清晰：**LLM 的语言表达能力越来越强也越来越有欺骗性**，自己因为是规则新手所以根本没能力鉴别哪些细节是真的。"如何辨别 LLM 提供的信息中哪些确有价值会变得更加重要。"最终还是靠自己读规则书 + BGG 论坛 FAQ 帖子解决，AI 辅助反而浪费了时间。

这和云风前一篇 [[sources/cloudwu-ai-reading-workflow|用 AI 辅助读书]] 里"LLM 加上下文能做文化映射（We/Our → 朕）"的正面例子形成鲜明对比——同一个工具，在"已有相当基础 + 验证成本低"的翻译场景里是好帮手，在"自己完全外行 + 错了也看不出来"的学习场景里反而是陷阱。

## 关键要点

- ST:CC 用 LOG / deploy / beam / 手牌保留 / 市场卡分流等多种机制做动态卡组控制，活动牌组稳定在 20 张内
- 初始卡组全独立设计 + 固定补充卡堆，不走 Dominion 同质化路线
- 卡片一卡多用 + 桌面位置极多 → 工人分配风格
- 每个初始牌组自带多步骤长线任务，强迫长远规划
- LLM 在冷门 / 新发布规则上的幻觉率很高，且**幻觉表现与正确答案完全无法区分**（自信满满、杜撰章节号、杜撰论坛引用）
- LLM 在有 ground-truth 可对照的场景好用，在新手完全外行的场景会浪费更多时间
- 人类玩家若没玩过游戏不会表现得如此自信——LLM 的"表达能力与实际知识"解耦是新的认知风险
