# 寻路算法-重新启发（gameKnife）

[[people/gameknife]] 于 2019 年 8 月 25 日的短文，记录作者在新项目中重新审视寻路系统的思考。项目是一个场景高频动态变化的游戏（可移动平台、断桥、地洞），传统 dynamic NavMesh 的生成成本压过了它对寻路本身的帮助。

## 摘要

作者先系统回顾了三种寻路算法——Dijkstra、Greedy Best-First、A\*——说明 A\* 通过启发函数 `h(n)` 在两者之间取得平衡，并指出把 cost 函数蜕化成极端时它恰好退化为 Dijkstra 或贪心。然后结合自己之前地形道路生成的经验讨论了 g 函数的设计：坡度、水域、曲率、阻挡四种代价如何塑造出"盘山公路"式的自然路径。文章最后讨论动态环境下的取舍：NavMesh 的烘焙成本在高频变化场景中不划算，作者倾向于回到基于 2D node 空间 + 多层连通 + A\* 变种的方案，通过局部重采样与缓存每步 g(n) 来维持效率。

## 关键要点

- A* 的 `f(n) = g(n) + h(n)` 公式是两极之间的滑动条：`f=g` 就是 Dijkstra，`f=h` 就是贪心。
- h 常用欧式距离以保证搜索收敛。
- g(n) 是把游戏性编码成代价的入口：坡度 / 水域 / 曲率 / 阻挡。
- g 代价越均匀搜索越慢（展开像水波），非均匀能快速收敛。
- 地形道路生成里把搜索限定到"以起终点中点为圆心、以起终点距离为半径"的圆形子空间，是个实用的空间裁剪技巧。
- NavMesh 在高频动态场景中 **生成开销 > 寻路收益**，考虑 2D node 空间局部重采样 + 多层连通。
- 可以研究 ARA\* / D\* / B\* 等 A* 变种做增量或限定时间预算的搜索。
