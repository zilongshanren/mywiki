# Z-order in top-down 2d games（Elias Daler，2013）

[[elias-daler|Elias Daler]] 2013 年 11 月发表的语言无关短文，专门讨论俯视角 2D 游戏怎么让"角色站在树后面"这种伪深度效果工作起来。作者用 *塞尔达：众神的三角力量* 做范例，把工业界两种主流 z-order 方案的原理与边界讲得很清楚。

## 摘要

俯视角 2D 没有真深度，遮挡靠**后绘制盖前绘制**实现，这就是 z-order。第一种方案是给静态精灵预设固定整数层级，并把树/房子拆成上下两片分别归到不同层（*ALttP* 就是这么做的）；好处是简单稳健，代价是每加一张图都要切图调层级，且对移动物体束手无策。第二种方案是**动态 Y 排序**：把屏幕上所有精灵按 `boundingBox.top + boundingBox.height`（底边 Y）从小到大排序后绘制，自动得到正确遮挡，无需手工标层。复杂物体（拱门、门洞）则引入"高度 z 轴"——同 z 层内做 Y 排序、跨 z 层按高度优先，让玩家"穿过"门洞时表现合理。性能上作者建议把静态对象的有序列表缓存下来，每帧只对移动对象重排再 merge。

## 关键要点

- z-order = 绘制顺序，后画的盖住先画的
- 静态层方案：固定整数层 + 预切图，简单但维护成本高、对移动物体无效
- 动态 Y 排序：按 box 底边 Y 升序绘制，自动正确遮挡，是现代 2D 渲染的标准做法
- 拱门类复杂物体：拆成多个 box + 引入"高度 z"，同高度内 Y 排序、跨高度按 z 排
- 这里的"z"是绘制层标签，不是真正的 3D 坐标
- 性能优化：静态物排序只做一次缓存，每帧只对动态物体重排并 merge
