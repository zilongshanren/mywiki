# SLIGE：Doom 随机关卡生成器

SLIGE 是 1990 年代由 David Chess 开发的 Doom 随机关卡生成器，以单个 14000 行 ANSI C 文件实现，通过读取配置文件和随机种子生成 WAD 文件。它是最早的 Doom 模改工具之一，后来因新手常将其生成的关卡冒充原创作品而在 Doom 社区声名大噪。Boris The Brave 对其源代码进行了深度分析。

## 架构概览

SLIGE 没有任何抽象层，所有生成操作直接操作 Doom 的底层数据结构：**linedef**（定义墙壁的线段）和 **sector**（描述区域的多边形，含天花板/地板高度及材质属性）。这与 Boris 分析过的 [[sources/boris-diablo1-dungeon]] 和 [[sources/boris-gungeon-dungeon]] 有根本性不同——后两者都有中间抽象层。

直接操作底层数据让作者拥有精细控制，但使简单操作变得繁琐。WAD 文件生成后还需要外部工具计算 BSP 树，这是 Doom 引擎渲染所必需的数据结构。

## 房间与连接

关卡由**房间（Room）**和**连接（Link）**构成，两者本质上都是轴对齐矩形。这一选择使生成结果有明显的方块感，但矩形内部支持多样的随机变体：房间可以有凹槽、秘密角落、机关、高台；连接可以是楼梯、电梯、传送门，或"孪生走廊"（递归调用连接生成函数）。

## Quest 栈式锁钥系统

SLIGE 用 **Quest 系统**实现关卡宏观结构，本质是一个**锁钥图（lock-and-key graph）**的栈式生成器：

1. 初始以"到达关卡出口"为目标创建一个 Quest，设定最小房间数
2. 每个房间有概率触发**分叉**：当前 Quest 入栈，启动一个新 Quest
3. 新 Quest 类型为 KEY / SWITCH / GATE / NULL 之一，分别在终点放钥匙、开关、传送门或小道具
4. 新 Quest 结束后弹栈，原有路径解锁，继续推进
5. 整个栈清空时关卡生成完毕

这产生了没有循环但有分支的树状路径结构。NULL 类型 Quest 不阻断主路，给玩家留有选择；其余类型均设置障碍要求玩家先完成支线。

## 难度预算系统

SLIGE 的难度调控出人意料地精细。它维护一份动态预算，追踪当前已生成内容下"一名技术熟练的玩家"在每种难度级别下剩余的血量、各类弹药量和护甲值：

- 每放置一个敌人，扣减对应资源消耗（取决于当前可用武器）
- 预算偏低时允许生成补给品（出现在 Quest 终点、秘密区域）
- 高难度会假设玩家更能把握补给物品的最优时机（如更晚捡护甲）
- 对机关区域，除最高难度外假设玩家会损失少量血量

这确保了资源分布始终处于合理范围，与当时大多数生成器随机堆放道具的做法形成对比。

## 关卡参数机制

在每张关卡生成开始时，SLIGE 一次性随机化大量**关卡参数（Level Settings）**，控制本关独有的特征概率（如纯电梯/纯楼梯、特定敌人出现率、是否有竞技场等）。这一机制有双重价值：

1. **一致性**：一张关卡内所有房间共享同一组随机偏好，视觉与玩法风格统一
2. **适者生存**：SLIGE 关卡以 WAD 文件形式独立传播，设定最成功的那批 WAD 自然会更多地被流传，为作者提供隐性反馈——SLIGE 在退出开发前共迭代了 485 个版本

## 与其他关卡生成器的对比

相比 [[dungeon-generation-algorithm]] 中分析的 Diablo 1（精细的预地牢图 + 递归细分）和 Enter the Gungeon（Flow 图 + Composite 布局），SLIGE 更简单直白：无抽象层、无图表示、纯矩形分解。然而它对游戏性细节的关注深度（难度预算、锁钥结构、关卡一致性）超过许多现代 roguelike。
