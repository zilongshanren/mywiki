# 把 xlsx 变成 diff 友好的文本格式

游戏项目里策划往往把数值、配置、文案全塞在 Excel 里。问题不是提取内容——xlsx 本质就是 zip 包裹的若干 xml 文件——而是 xlsx 对版本管理工具极其不友好：**打开再保存就会生成一个完全不同的新版本**，因为文件里记录了最后修改时间（Excel 不信任文件系统的时间）和当前激活的单元格。多人协作一冲突就是一堆二进制级别的 merge 地狱。

[[cloudwu]] 在 2025 年 9 月的笔记里记录了一个"弯路方案"：不做 Excel 插件，而是**做一个可逆的文本格式转换**。

## 思路

核心是把 xlsx 规范化成一个纯文本形式，供 git 做行级 diff：

1. **解 zip**：用 Lua 的小程序把 xlsx 内部文件全部读出。
2. **排序**：按文件名字典序排，消除顺序带来的噪音。
3. **拼接**：按"文件名 / 文件内容"的次序连在一起，形成一个大文本文件。
4. **对二进制做 base64**：嵌入的图片一般不会改，base64 之后在 diff 中保持稳定。
5. **给 xml 标签后加换行**：让行级 diff 真的能对齐到"哪一个单元格改了"。
6. **剔除无语义字段**：抹掉"最后修改时间"、"激活单元格"等无意义但会引起差异的字段，从而即使空打开再保存也不会产生版本差异。

这一步之后，xlsx 就退化成一个普通的文本文件，git / svn 都能正常 diff 与合并。

## 让 Excel 仍然能编辑

新格式如果 Excel 不能直接打开就没人用。比起写 Excel 插件（又是一两天的工程），作者选了个取巧方案：

- 文件关联到一个十几行的 Lua 脚本。
- 双击时，脚本把自定义文件转成临时 xlsx，交给 Excel / WPS 打开。
- **用文件锁做结束判定**——Excel 对打开的文件会加锁，脚本监控临时文件的 mtime 和可写状态，一旦变为可写就意味着用户关闭了文件，此时把临时 xlsx 反向转回自定义格式并删除临时副本。

整条链路不动 Office 自身、不装插件，只在文件系统层做了一个包装。代价是用户感知到"保存有延迟"——需要关文件后同步回去——但换来了 git 能正确 merge，以及策划从 svn 迁到 git 后不再被冲突吓退。

## 为什么这是"半成功"

作者自己评价：**不算成功也不算失败**。一个 xlsx 格式细节上藏着非常多"对版本控制不友好"的点，并不是两小时能扫清的。文章没有写完的部分包括：

- 某些字段与单元格位置相关的间接引用在排序后可能失去局部性。
- 图片以外的其他二进制资源（如内嵌 OLE、图表二进制）未必都能稳定化。
- 团队协作时，自定义格式的双人同时编辑仍要走 git 的 merge，而策划并不擅长解决 merge 冲突。

所以这是一个"工程上解决一类问题但不是所有问题"的务实方案，写出来主要是记录踩过的坑，而非推荐大家原样照搬。
