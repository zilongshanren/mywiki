# 跳跃洪填算法（Jump Flooding Algorithm, JFA）

**JFA** 是一种在 GPU 上高效生成 **距离场（distance field）** 的多趟算法：给定一张带 alpha 的纹理，它能在 O(log N) 次 pass 内为每个空像素求出「离最近不透明像素的距离以及方向」。结果可以直接驱动描边、光晕、软投影、扩散光照等一大类效果，而不需要离线烘焙 SDF。它是 SDF 家族里**最适合实时管线**的构造方法之一，也是 shader art 和工具链里非常常用的原语。

## 为什么不是暴力搜索

对每个像素到每个其它像素做最近点查询是 O(N²)，一张 1024×1024 的图就上亿次比较，实时完全不可行。JFA 用的是「每一趟都以指数缩小的步长传播已知信息」的洪填思路：第一趟用 `jump = 64` 采 3×3 邻域，第二趟 `32`，第三趟 `16`，……直到 `1`。总 pass 数 = `log2(max_radius)`，每趟每像素只读 9 个 texel。

## 单趟的本质

对每个像素：

1. 以当前 `jump` 为步长，采周围 3×3 的 9 个样本（含自己）。
2. 每个样本携带「它自己记忆的、最近不透明像素的 **相对偏移**」。
3. 把这个偏移加上采样方向得到「从本像素出发的候选距离向量」。
4. 取所有候选里距离最短的，写回到输出——继续把**最近不透明像素的相对偏移**编码进 RG 通道。

这里的妙处是「信息可以沿着样本的样本的样本传播」——一次 pass 的有效传播半径等于 `jump`，log 趟下来就覆盖了整张图。

## 编码技巧

Xor 的实现把偏移量压进 8-bit RG 通道：`rg = offset / 255 + 127/255`，相当于用 [-127, +128] 范围表示偏移。这样一张普通 `RGBA8` 表面就能跑 JFA，不需要浮点纹理；代价是最大有效半径 127 texel。如果需要更远的传播就换浮点格式。Alpha 通道顺便保存「1 - 反距离」，方便后续直接采样做柔化。

## 直接可以做什么

- **描边 / 硬边轮廓**：对 JFA 输出按 `dist < threshold` 二值化。
- **光晕（glow / bloom halo）**：按距离做指数或线性衰减。
- **软投影 / 软阴影假效果**：离主体越远越淡。
- **完整 SDF**：同时对内部也跑一遍（或对反转 alpha 跑），就能得到真正意义上的有符号距离场，用于 **字体渲染（MSDF）**、UI 圆角、流体边界、2D 物理近似。
- **路径寻径 / 影响图**：游戏逻辑层也可以拿 GPU 算出的距离场当启发式。

## 与其它距离场方法的对比

- **暴力 brute force**：O(N²)，只适合离线。
- **8SSEDT / Dead Reckoning**：CPU 上两趟扫描即可，精度较高，但对 GPU 并行不友好。
- **JFA**：O(log N) 趟、每趟都是完美并行的 3×3 采样，天生匹配 [[fragment-shader|fragment shader]] 的工作模型。精度略差于 8SSEDT（「跳出格子」时可能略失一个像素），有多种改进变体（JFA+1、1+JFA）。

JFA 是一个很好的例子：**一个简单的「每趟指数缩小步长」的想法**，一旦和 GPU 的并行性对齐，就能把 O(N²) 的问题压到工程可用的范围。
