# ASCII 字符不是像素：形状向量法

大多数图像→ASCII 渲染把每个字符当成一个可变亮度的「像素」，结果就是 Cognition 着陆页那种糊掉的边缘。Alex Harri 用另一套思路重写这件事：**把字符看作有形状的向量**，用最近邻查找在形状空间里匹配图像局部，再叠两层对比度增强让边界变锐。

## 传统方法的天花板

朴素实现：把图像切格、每格取中心像素的相对亮度（`0.2126·R + 0.7152·G + 0.0722·B`）、按亮度区间映射到 `"  .:-=+*#%@"` 之类的字符梯度。这本质上就是**最近邻下采样 + 调色板量化**，必然出现 [[aliasing|jaggies]]。加超采样（每格取多样本求均值）只能让它从像素锯齿变成像素模糊——边缘看起来「柔」但依然是低分辨率位图，**因为所有采样都被压缩成一个标量亮度值，字符形状完全没进入决策**。

## 形状作为高维向量

作者把每个字符的可视分布量化成**一个 N 维形状向量**：

- **2D 起步**：在字符格的上下半区各放一个采样圆，统计字形像素覆盖比例。字符 `T` 得到 ~(0.6, 0.1)，`L` 得到 ~(0.1, 0.5)。所有 ASCII 字符归一化后落在 2D 平面上。
- **升到 6D**：上/中/下 × 左/右 共 6 个采样圆（左右列垂直错位 + 加大半径以覆盖 `-`、`.`、`/` 这类位置敏感的字形）。6D 形状能区分 `p` vs `q`、`^` vs `-` vs `_`。

运行时，**对要渲染的图像每格也采出 6D 采样向量**，用欧氏距离做最近邻查找：

```js
findBestCharacter(sampleVec)  // 遍历所有字符，argmin |shapeVec - sampleVec|
```

查找结果显著优于亮度映射：字符真正「贴着轮廓走」，圆、曲面、斜边都变锐。本质上这是用**字形嵌入空间**做模板匹配，作者自己指出这与 word embedding 的思路同构。

## 两层对比度增强

6D 直出的 3D 场景内部仍显糊——不同亮度面之间的边界不够硬。对策是两级 contrast enhancement：

1. **Global**：对每格采样向量做「归一化 → 提幂 → 反归一化」，仅压暗低分量、保住最亮分量。避免整体变暗，只放大向量内部的对比。
2. **Directional**：在格外部一圈布 10 个外部采样圆，每个内部分量对应一组外部分量（`AFFECTING_EXTERNAL_INDICES`），取外部最大值作归一化基准。这让边界一侧的亮像素**方向性地**推暗另一侧，消除单靠 global 在「整格全变暗」时的 staircasing 阶梯纹。

组合两层后，正方形/立方体/球面的内部边界清晰锐利，渐变区保持平滑（均匀向量对提幂不敏感）。

## 性能：查找与采样都吃不消

- **查找**：6D 中 [k-d 树](https://en.wikipedia.org/wiki/K-d_tree)性能已劣化（维度诅咒），作者补了**量化缓存**——每分量 5 bits，6 维拼进一个 30-bit 整数 key，命中即跳过距离计算。
- **采样**：3D 场景每帧要为每格收集约 60–120 个样本（内部 + 外部 + 若干超采样），CPU 在 iPhone 上几乎瘫痪。最终整条管线（6 个 pass：采内部、采外部、算外部最大值、directional 增强、算内部最大值、global 增强）搬到 GPU，跑通实时帧率。

## 价值

方法本身（高维向量表征 + 最近邻 + 对比度增强）超出 ASCII 渲染。作者明确指出这适用于任何「把高分辨率细节降采样到有限符号集合」的问题——只要你能为每个符号构造一个有意义的形状/语义向量，就能用近邻搜索取代亮度量化。
