# 实时渲染：质量 vs 数量的结构性取舍

实时渲染团队面临的根本困境不是技术，而是**激励结构**：「加一个新功能」远比「把已有功能做到极致」更容易在排期、trailer 和会议上被认可。这种结构性偏见导致视觉质量系统性地被牺牲给功能数量。

## 为什么「数量」总赢

- 新功能可以列入排期表，完成后有明确的 done 状态
- 新功能可以放进预告片字幕、写进 back-of-box 卖点
- 质量是无形的感受，难以 demo、难以量化、难以汇报
- 「这个功能在 game 里跑通了、没有崩溃」→ 被视为 done，质量门槛从未进入验收流程

## 「被感受到而非被看见」

Angelo Pesce 的核心论断：优秀的渲染技术应当通过整体氛围、材质真实感、光影层次**被感受到**，而不是作为可辨认的技术特征**被看见**。一旦玩家能识别出「这是一个渲染技巧」，就已经是失败。

典型的失败模式：
- LOD 溶解效果过于明显——玩家不需要那块石头，但石头溶解时暴露了「渲染技法的存在」
- 过曝的 bloom + 不稳定的 vignette + 过度 lens flare 堆叠在一起——是掩盖低质底层的化妆，而非提升

## Pixar 的「不做」原则

Pixar 制作《玩具总动员》时有意回避有机生物（人类角色），因为他们判断当时无法把这类内容做到足够高的质量。宁可把问题范围限定在可以做好的边界内，也不做出来让人看见破绽。这种「如果做不好就不做」的纪律，在游戏行业极为罕见。

## 「从零开始只做精」的思想实验

Pesce 提出：如果从基础的前向渲染 + 烘焙出发，只做好这几件事——

- stable CSM 阴影（一条方向光）
- 纹理压缩与 mip filtering 的感知调优
- 正确的 specular prefiltering 与 Fresnel 实现
- 精确的 HDR tonemapping（不是帧缓冲有 HDR 就叫 HDR，要正确 tonemap）
- 感知驱动的 LOD 策略与 AA 策略

……花一两个游戏周期把这些做到极致，输出的视觉品质可能超过同时代大多数功能堆砌的作品，并且能发出若干篇研究论文。

## 行业真正缺乏什么

技术能力（着色模型、抗锯齿方案、后处理算法）的积累速度快于两种能力：

1. **视觉品味**——理解什么在感知层面真正重要
2. **生产流程**——把质量目标转化为可验证的验收标准（A/B 测试、生物特征测量、眼动追踪）

「渲染已解决」是误判。即便在离线渲染和理论层面，渲染问题也远未解决。
