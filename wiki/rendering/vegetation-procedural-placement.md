# 程序化植被散布系统

实时游戏中，大场景植被（树木、灌木、岩石等）的分布通常不能手工摆放，需要程序化地根据艺术家绘制的**密度图**生成实例位置，同时保证自然的分布感（无明显网格感、无相互穿插）以及足够的变化（不同大小的对象相互适应位置）。

[[angelo-pesce]] 在 COD: Black Ops 4 的"Blackout"大地图中负责了此类系统的 R&D，形成了一套实用的解决方案。

## 核心设计：固定点集 + 可控排列

与 GPU 实时生成的思路（参见 Horizon Zero Dawn 的 GPU 驱动方案）不同，BO4 的方案是**编辑时生成、运行时流式加载**。这绕开了实时生成的性能与内存压力，也使得艺术家能以接近实时的交互速度（CPU + GPU 辅助）调整密度图，立即预览结果。

**点集生成**：用 Mitchell 最佳候选算法（best-candidate algorithm）生成初始蓝噪声点集，再通过松弛迭代使点分布更均匀（过度松弛会退化为六边形网格，需要平衡参数）。不同图层对应不同世界空间尺度的瓦片大小，使得同一套点集可服务于不同尺寸的对象。

**激活排序与密度映射**：对点集生成多套"排列顺序"（permutation），决定当给定一个密度值时，哪些点被激活。一个好的排列保证"前 K 个点永远是好的蓝噪声"——与[[poisson-disk-sampling]]中分层蓝噪声的思路一脉相承。用密度图采样当前瓦片的密度值，换算为激活点数，再按序号激活。不同排列风格产生不同视觉效果：均匀扩散、随机、簇状聚集、绳状分布等。

## 多图层影响机制

植被被组织为若干图层，大对象（树）在上层先评估，小对象（岩石、灌木）在下层。上层图层在已放置对象周围一定半径内对下层施加**负密度偏置**（排斥），或在对象外一定环形区域施加**正密度偏置**（吸引）。这使得"石头聚集在大树旁、草丛远离树根"等自然共生关系能以参数化方式表达，无需手工摆放。

## 存储与空间编码

最终每个瓦片只需保存图层参数和一张**位图（bitmask）**，哪个点激活就置对应比特为 1。将点集按空间局部性重排（空间填充曲线或旅行商优化），密集区与稀疏区在位图中形成连续的 0/1 游程，再施加**游程编码（RLE）**，体积极小。运行时的实例化渲染直接消耗这张位图生成 draw instance 调用，与[[batching]]和[[gpu-driven-grass-tiles]]的实例化方案对接。

## 与 GPU 驱动方案的比较

[[gpu-driven-grass-tiles]] 走的是另一条路：蓝噪声预烘焙分布 + GPU Compute 剔除 + 间接绘制，完全在运行时由 GPU 决定可见实例集合，适合密度极高、视距极远的草地。BO4 的方案选择编辑时生成是因为需要支持复杂的多层次对象相互影响逻辑，这种逻辑在 GPU 上实现代价更高，而运行时性能已经足够——草地由单独的专用系统处理，使植被层的实例数目大幅降低。
