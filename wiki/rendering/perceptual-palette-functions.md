# 感知均匀调色板函数（Perceptual Palette Functions）

在 shader 或 C++ 中做调试可视化时，最常见的做法是把数值直接映射到 RGB 三个通道（「coder colors」）。这个做法直观、零依赖，但在感知上是有问题的：人眼对三个通道的敏感度差异悬殊，绿通道感知亮度约是蓝通道的三倍，导致不同通道的数据在视觉上权重不平等。

本页汇总以**感知均匀色彩空间**为设计基础、适合嵌入 shader 或 CPU 代码的调色板函数。

## 设计原则

- **感知均匀**：调色板中相邻颜色的感知差异应均匀，以 JND（Just Noticeable Difference）为步进单位
- **CIELAB / CIELCH 路径**：在 CIELAB 空间中沿曲线路径设计，比在 RGB 或 HSV 中线性插值更准确；CIELCH / HSLUV 等圆柱变换可方便地生成带色调旋转的均匀渐变
- **以亮度为主，色调为辅**：为对色盲用户友好，主要信息由亮度携带，色调只是增强对比度的辅助手段（参见 [[color-blindness-accessibility]]）
- **可区分 >10 档**：通过利用亮度 + 色调两个维度，比纯灰度的 6~7 档有效提升
- **避免纯黑/纯白**：sRGB 暗端感知非线性极差，亮端容易出现通道饱和

## Pesce 2017 调色板函数套装

[[people/angelo-pesce]] 在博文中给出了一组拟合到简单多项式 / 正弦函数的 GLSL 函数，故意不使用向量类型，方便跨语言复制：

### 顺序一维数据（0→1）

```glsl
vec3 ColorFn1D(float x) {
    x = clamp(x, 0.0, 1.0);
    float r = -0.121 + 0.893*x + 0.276*sin(1.94 - 5.69*x);
    float g = 0.07 + 0.947*x;
    float b = 0.107 + (1.5 - 1.22*x)*x;
    return vec3(r, g, b);
}
```

风格类似 Viridis（Matplotlib 默认感知均匀 colormap），正弦分量源于 CIELAB 圆柱变换的自然曲线特征。

### 发散一维数据（-1→1）

```glsl
vec3 ColorFn1Ddiv(float y) {
    y = clamp(y, -1.0, 1.0);
    float r = 0.484 + (0.432 - 0.104*y)*sin(1.29 + 2.53*y);
    float g = 0.334 + (0.585 + 0.00332*y)*sin(1.82 + 1.95*y);
    float b = 0.517 + (0.406 - 0.0348*y)*sin(1.23 + 2.49*y);
    return vec3(r, g, b);
}
```

适合显示正负偏差（误差、速度分量、差值图）。

### 单维数据 + 分类标签（2类）

两套亮度相近但色调可区分的调色板，通过 `int c` 参数（0 或 1）选择。适合同时显示两类物体的同一维度数据。注意：两套调色板不能过亮/过暗，否则色调区分度下降。

### 二维数据

将两个独立维度映射到感知线性处理后的红/绿（或红/蓝）通道，含 gamma 重映射步骤以补偿 sRGB 暗端非线性。

## 与相关工具的对比

| 工具 | 适用场景 | 形式 | 是否可嵌入 shader |
|------|----------|------|-------------------|
| [[perceptual-colormaps]]（Matplotlib 烘 LUT） | 离线图表、截图 | .cube 文件 | 需要纹理采样 |
| 本页的 GLSL 函数 | 实时调试覆盖、GPU debugger | 内联代码 | 直接嵌入，无纹理依赖 |
| Viridis / Inferno 多项式近似 | 通用 | 5阶多项式 | 可嵌入，精度更高 |

函数形式的主要优势是**零外部依赖**：不需要纹理采样、不需要 LUT，复制粘贴即可在任何着色器、调试 pass 或 CPU 工具函数中使用。

## 注意事项

- `ColorFn1D` 中蓝通道公式有一个已知的符号笔误（见原文评论），实际使用应注意验证
- 这些函数是手工拟合的，并非严格的感知均匀——对于发表级别的可视化，建议使用经过严格验证的 Viridis/Cividis 等
