# Creative Coding 的工作流

**Creative coding**（创意编程）是把代码当作画笔而不是工具的编程流派——它的目标不是"实现一个功能"，而是"做出好看 / 有趣的东西"。[[xor-shader-artist|Xor]] 把自己写 shader art 的流程拆成四步：**灵感 → 原型 → 打磨 → 迭代**。和[[shader-code-golfing|code golfing]] 一样，它锻炼的是和"工程师式 shader 写作"完全不同的肌肉。

## 灵感：抓一个具体目标

一切从"想做什么"开始。Xor 常用两种套路：**想一个我没见过的东西**（例：虫洞），或**翻参考图**。关键是让目标**在你当前的技能半径内**——第一次写 shader 的人不要冲 3D，先挑自己已经懂一点的材料（会一点噪声，那就去做云 / 地形 / 洞穴）。

## 原型：把最基本的想法跑起来

不要先纠结细节。虫洞的核心想法是：**把一张贴图往中心拉，再绕着中心拧一圈**。写成代码就是把直角坐标换成极坐标：

```glsl
vec2 uv = vec2(length(p), atan(p.y, p.x) / PI - length(p));
```

`length(p)` 是到中心的距离、`atan(p.y, p.x)` 是角度、减去 `length(p)` 就得到了一个螺旋扭曲。跑起来——哪怕丑——比不跑强。

## 打磨：修掉第一轮的"明显问题"

原型跑起来之后总有毛病：

- **`atan` 的间断线**：`atan` 在 y=0 水平线上从 -π 跳到 +π，贴图过滤会把这一跳放大成一条可见的缝。修法是人工把两半连起来——`p.x > 0` 时用 `atan(p.y, p.x) / PI`，否则用 `1.0 - atan(p.y, -p.x) / PI`，让函数看起来连续。
- **螺旋扭曲不均匀**：线性极坐标下，中心扭得太少、边缘扭得太多。改用 **log-polar 坐标**——用 `log(length(p))` 替代 `length(p)` 作为半径——扭曲就变成尺度不变的，靠近中心和远离中心拧的角度一样多。顺手还让动画好写：`log(length(p)) - seconds * 0.5`。
- **调色**：最后给灰色贴图乘一个带色 vec4 `vec4(0.5, 0.8, 1.3, 1.0)`，冷蓝调就出来了。

## 迭代：让结果告诉你它想变成什么

到这一步，代码已经是"差不多能看"的状态。接下来的所有工作都是**调参 → 观察 → 再调参**的循环。Xor 的经验是，他本来想做虫洞，玩着玩着发现这东西更像**飓风**——这完全没关系，经常会**在调参过程中撞上比原定目标更好的效果**，跟着那个效果走就是。借别人的代码也一样：动手改几个常数，往往比读懂它学到的东西还多。
