# 细胞纹理的离线生成

[[worley-voronoi-noise|Worley / Voronoi 噪声]] 在现代 shader 里通常作为**实时节点**求值：每个像素扫相邻 3×3 个网格格子，跑 9–27 次哈希即可。但在 Werkkzeug3 这类 demoscene 纹理生成器（ryg 参与过的项目）里，问题完全反过来——**离线**算整张 1024×1024 的细胞纹理，点集是任意位置而非固定网格的散点。这时性能瓶颈变成 _all-nearest-neighbors_：对 `|G|` 个像素求到 `|C|` 个散点里最近两个点的距离。[[fabian-giesen|Fabian Giesen]] 2010 年在 ryg 博客的两篇连载完整地对比了五种算法，核心结论是：**「用树」这条路是反而最糟糕的选择之一**。

## 五种算法的赛跑

ryg 在 1024×1024 图像、随机点集、Core 2 Duo 2.2GHz 单线程上测得（毫秒级，见原文表格）：

- **暴力法**：每像素对所有点求距离，用 (best, best2) 淘汰。64 点 710ms，512 点 7.2 秒。
- **点定位树**（kd-tree 风）：每像素从根下降找最近两点。64 点 1.7 秒——**比暴力还慢**。原因是忽略了查询端（像素网格）的结构：相邻像素几乎要复用整条路径，但每次都得重走。
- **sort by y**：每扫描线把所有点按 y-距离排序（插入排序几乎 O(n)，因为下一行基本有序），一旦 `best2 < dy²` 就停。64 点 148ms，512 点 330ms。**相对树快一个数量级**，代码仅 60 行，且天然 SIMD 友好（4 个像素并行处理直到全部收敛）。
- **tiles（小方块分块）**：按 32×32 像素的 tile 为单位，算每个散点到 tile 的**距离下界**作为排序 key，然后 tile 内逐像素跑 sort-by-y 风格的 rejection。对称处理 x/y 两个轴，修了 sort-by-y 在非均匀度量下的尴尬。
- **spatial subd（空间递归细分）**：真正的杀手锏。矩形 `R` 递归地四分成子矩形 `S`，每次缩水时检查距离下界——**如果 `S` 内至少有两个点，那么所有可能成为 `S` 内像素最近两点的候选点都必须落在以 `S` 为中心、边长三倍的扩展矩形 `S'` 内**。把 `S` 外的点直接丢掉继续递归，直到矩形足够小再用 tiles 算法实际着色。1024 点时只要 41ms，比 sort-by-y 快 5×、比树快 140×。

## 为什么树反而输

这是 ryg 本文的核心理论观察：点定位结构把查询端（像素网格 `G`）当成无结构的独立查询流，对每个像素从头下降；可真正要解决的是 _all-nearest-neighbors_——你应当**利用 G 的规则网格结构**，对一整块像素一次性剔除大部分候选点。代价是：如果硬要写 all-NN 风格的树算法，代码量会比 spatial subd 还大，工程上完全不合算。

## 一个可以照搬的着色技巧

ryg 顺手给了一个改进 Jim Scott 原始配色的公式：

```
(dist2 - dist1) / (dist2 + dist1)  ==  1 - 2·dist1 / (dist1 + dist2)
```

效果近似 `dist2 - dist1`（边缘高亮），但各 cell 间的亮度**归一化**了——不会因为远离散点的 cell 整体变暗。

## 教训

这两篇文章的元信条是：**看清问题的结构比套经典数据结构更重要**。教科书上，最近邻搜索 = kd-tree / BSP；但当查询集本身有规则结构，对查询集递归细分才是对的。这和 metaballs 等值面抽取里的空间八叉树剔除思想是同构的——先按 _空间_ 聚合，再在每块空间里裁掉距离太远的点。
