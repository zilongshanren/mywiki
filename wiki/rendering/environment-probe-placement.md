# 环境探针辅助放置（Assisted Environment Probe Placement）

**环境探针**（environment probe / reflection probe）是实时渲染里为局部反射与间接光照提供近似的小型立方体贴图采样点。现代游戏关卡里往往需要成百上千个这样的探针：美术需要手工扫过整个关卡，在每个走廊拐角、每块金属墙面、每片水面旁边插一颗，然后再回头清理冗余的、位置相近的探针。内容一旦改动，这个过程基本要重来。Chajdas、Weis、Westermann 2011 年在 *Assisted Environment Probe Placement* 里把它变成了一个「预处理 + 辅助建议」问题：算法生成一批候选位置，美术只需要挑选、微调、加减。

## 算法思路

文章对算法只给了一个相对抽象的描述，要点是：

- **候选位置由游戏内渲染器生成**。不必靠光线追踪——作者在论文里虽用了 ray tracing，但在实际生产里，in-game renderer 可以用 100+ 个探针 / 秒的速度生成候选图，使得预处理时间可接受。
- **采样密度**是主要参数。典型设置是「每米一个探针」，这相当于在整个关卡里撒一张规则点阵。
- **相似度度量 + 聚类消除**控制最终探针数量。算法会评估相邻候选探针的视觉相似度：越相似的越可能被合并。聚类的代表探针先尝试放在聚类中心；如果中心不是好候选（按相似度度量判定），则把聚类拆开，必要时甚至要在聚类内部做 pair-wise 比较，把空间上靠近但视觉上不同的探针分开。
- **梯度驱动的搜索**导致一个已知失败模式：**阴影区域**里所有相似度梯度都指向外部光照充足的区域，算法因此永远不会把探针塞进纯阴影角落。把搜索方向反过来也不行——那样靠墙的探针又会变成「吸点」。这是一个典型的 [[debug-visualization|可视化辅助 workflow]] 需要暴露给美术、让他们手工补点的坑。

## 它替代了什么

传统流程里美术必须:

1. 手工走遍关卡，目视估计哪里需要反射；
2. 在每个位置放一颗探针，烘焙；
3. 对比视觉结果，删除冗余探针；
4. 场景改动后重复上述全部。

辅助算法把 1 和 3 自动化：给出一张密度受控的候选点集 + 每点附带信息（影响范围、相似度群组等），美术主要的工作变成 *筛选* 与 *微调*。论文的早期用户测试声称单个关卡能节省约半天工作量。

## 留给读者的 gap

文章是研究项目主页级别的摘要，并没有完整算法细节。以下内容本 wiki 只能从原文字面转述，无法独立验证：

- **相似度度量**的具体形式（是 L2 差异还是感知度量？）作者没有展开。
- **实际部署**情况：文章只提到「初步用户测试」，缺乏真实游戏管线里的长期数据。
- **动态反射探针**（如延迟探针 / 屏幕空间反射回退）与本算法的关系未讨论；2011 年写作时 SSR 尚未成为主流。

这些都是 LLM 补档时应该明确标注为未知的环节。
