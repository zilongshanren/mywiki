# 体素 LOD 超大网格渲染

实时渲染数亿三角形的多边形网格面临三个纠缠在一起的子问题：**流式加载**（内存/显存装不下全部几何体）、**遮挡剔除**（绝大多数三角形在任何视角下都不可见）、**LOD**（远处细节不需要全精度）。传统做法把三者拆成独立系统，互相之间需要同步；Chajdas 等人的方案把三者统一进单个光栅化管线。

## 体素 LOD 的核心思路

传统网格 LOD（如 Quadric Error Metrics 简化）为每个 LOD 级别生成独立网格，存储冗余且简化质量对极高面数网格不稳定。体素化方案改为：

1. 把原始网格体素化到一个稀疏体素格（Sparse Voxel Grid）；
2. 每个 LOD 级别对应一个更粗的体素分辨率——分辨率减半即 LOD 降一级；
3. 渲染时把体素格直接光栅化（体素 → 小正方形 / billboard 或 solid voxel），而不是三角形网格。

这种方案的优势是 LOD 生成速度快（体素化比网格简化快得多），不同 LOD 级别之间的切换没有网格连续性问题（体素本来就是离散的），而且紧凑——每个体素只需要位置和材质信息。

## 三合一管线

整个系统在单个光栅化 pass 里完成：

- **流式**：摄像机视锥 + LOD 级别决定需要哪些体素 tile 在显存里，调度器流式加载缺失的 tile。
- **剔除**：不可见（被遮挡或视锥外）的体素 tile 直接跳过，无需单独的 Hi-Z prepass。
- **LOD**：按屏幕空间误差自动选择体素粒度，远处用粗体素，近处用细体素或原始三角形。

避免多 pass 同步是这套设计的核心工程收益——传统三件套方案每轮之间都需要 UAV barrier 或 render target 读回，造成流水线停顿。

## 与 Nanite 的对比

[[nanite-reyes-comparison]] 的 Nanite 同样把流式 + 剔除 + LOD 统一，但走了完全不同的路线：Nanite 用 meshlet（小三角形 cluster）+ 软件光栅化（针对小三角形）+ 虚拟几何体（近似无限精度的三角形预算）。两者的分歧点：

| | 体素 LOD 方案 | Nanite |
|---|---|---|
| LOD 表示 | 离散体素格 | Meshlet DAG（连续精度） |
| 光栅路径 | 纯硬件光栅 | 软件光栅（小三角）+ 硬件光栅（大三角） |
| 抗锯齿 | 硬件 AA，高质量 | 需要 TAA 配合 |
| 生产就绪 | 研究原型 | Unreal Engine 5 主力管线 |

体素方案在"几何形状能容忍体素近似"的情况下（地形、岩石、建筑体量）有成本优势；Nanite 更通用但系统更复杂。

## 已知限制

- 体素近似对**薄结构**（树叶、栏杆、电线）会丢失细节；
- 体素 → 三角形的边界过渡（LOD transition seam）需要处理，否则会有体素化的"阶梯感"在 LOD 切换时闪烁；
- 材质支持比三角形 mesh 受限——体素格上的 UV、切线空间等属性需要额外存储。
