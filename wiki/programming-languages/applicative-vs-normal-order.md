# 应用序 vs 正则序

两种求值时机的设计选择。

## 应用序（Applicative Order）

**先求值参数，再调用函数**。大多数主流语言（C/C++/Java/Python/JS/Rust）都是应用序。

```
(f (g 5))   ; 先求值 (g 5) = 10，再 (f 10)
```

## 正则序（Normal Order）

**把参数表达式直接代换进函数体，用到时才求值**——**惰性求值**的基础。

```
(f (g 5))   ; 代换为 f 的定义，只有在需要 x 时才求 (g 5)
```

Haskell 采用（的一种变体：call-by-need，有记忆化）。

## 权衡

| | 应用序 | 正则序 |
|---|---|---|
| 求值次数 | 每参数一次 | 参数被用到几次就求几次（朴素） |
| 副作用可预测性 | 高 | 低（求值时机不确定） |
| 无穷数据结构 | 不支持 | 自然支持（只求值前 N 项） |
| 调试 | 易 | 困难（延迟执行） |
| 性能预测 | 易 | 难 |

## 工程后果

应用序与**命令式副作用**相容——这就是主流语言都选应用序的根本原因。正则序让你写优雅的代码（Haskell 的 `take 10 primes`），代价是性能模型变得不可直观推理。
