# 环检测：Floyd 与 Brent 算法

单链表最常见的「不包含非法指针但结构已坏」的 bug 是自身成环——通常是把同一个节点 `x` 第二次插进链表时触发：若新位置在旧位置之前或等于旧位置，你得到一个环；若在旧位置之后，新旧位置之间的节点被悄悄摘掉。ryg 在 [[data-structure-invariants]] 一文之后顺手补了这一篇，主要想提醒工程师：调试单链表时有一对「基本不占内存」的环检测算法可用，值得记住。

## 为什么不用「访问位」

给每个节点加一位 visited 标记看似简单，但清理这些标记本身就要遍历链表——而那条链表可能正在坏掉。于是你需要一种在任意图/链表上原地工作、只用 O(1) 额外空间的检测法，Floyd 和 Brent 的算法都是这样。

## Floyd 龟兔

两个指针同时走，慢指针每次走一步，快指针每次走两步。若存在环，快指针会在环内追上慢指针；若不存在，快指针会走到终点。经典、直观，也是教科书最常讲的版本。

## Brent 的变体

Brent 的做法更有意思：它把慢指针在每个「回合」固定不动，让快指针独立前进 2、4、8、16……步，每个回合结束把慢指针拉到快指针位置开启新一回合。实际测量下，Brent 的总步数通常比 Floyd 少 20%–30%。

ryg 指出 Brent 其实是**迭代加深**（iterative deepening）的一个实例——正是极小极大搜索里的那种加深：每一轮都从头重跑，但因为深度以指数增长，「白跑的部分」总和仍在最优答案的常数倍以内。相同的思想可以在任何需要限定栈/内存、又不想一次走到底的搜索问题里反复使用。

## 附带的小谜题：铁轨上找人

评论区里还给出一个相关的小谜题：你空降到一条双向无限铁轨上，同伴也在轨道某处、方向未知，你的最优搜索策略是什么？答案是指数式来回——先走距离 d，回原点再反向走 c·d（c>1），再回来走 c²·d……总行走距离在最优解的常数倍以内。这是经典的**在线搜索 / 牛头比赛（cow path problem）**问题，和 Brent 算法共享同一个「指数加深保证常数竞争比」的思想骨架。
