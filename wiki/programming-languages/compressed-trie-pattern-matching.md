# 压缩 trie 作为后缀模式学习器

Alex Harri 的 [beygla](https://github.com/alexharri/beygla) 库把约 3,600 个冰岛人名的格变规则压进 **3.27 kB gzipped** 的 trie。核心洞察：trie 压缩不止是省空间，**还能让这棵树自己从数据中「学」出后缀→变格模式的规则**，对未见过的名字也能正确推断。

## 问题与数据结构

冰岛语名词有四个格（主、宾、与、属），数据库里永远存主格，界面要按句法选正确形式。Iceland 公开的 K-format（[Árnastofnun](https://bin.arnastofnun.is/DMII/) DIM 数据集）加上已批准名字清单，给出约 3,600 条形态四元组。每条先按「最长公共前缀」拆成 suffix encoding：

```
Guðmundur / Guðmund / Guðmundi / Guðmundar
公共前缀 "Guðmund"，后缀编码 "ur,,i,ar"
```

这个编码**不绑定具体名字**——它描述的是一种变格模式（pattern）。

## 关键：倒序插入

所有 key 以**倒序字符**插入 trie。这样相同后缀的名字会落在同一子树下。例如 `Knútur / Hrútur / Loftur` 都走 `r→u→t` 路径到达 rut 子树，它们的后缀编码都是 `"ur,,i,s"`。

## 子树压缩：当所有叶子值相同时折叠

`compress` 递归函数深度优先收集子节点值；若所有子节点值相同，则把值搬到当前节点、删除所有子节点。经过这一步：

| | 原始 | 压缩后 | 比例 |
|---|---|---|---|
| 总节点 | 10,284 | 1,588 | 15.4% |
| 非叶节点 | 6,646 | 327 | 4.9% |
| 叶节点 | 3,638 | 1,261 | 34.6% |

**超过 95% 的非叶节点被消灭**，也就意味着查询深度大多只需 3 个字符级后缀。

## 从记忆到推断

压缩后，lookup 不再要求完整路径匹配——`trieLookup` 在无子节点时返回**最近的有值节点**即可。这带来神奇的泛化能力：

- 所有匹配 `*tur` 的名字返回 `"ur,,i,s"`
- 所有匹配 `*fur` 的名字返回 `"ur,i,i,ar"`
- `*ur` 但既不 `*tur` 也不 `*fur`（例如 `Sakur`）落到无值的 u 节点，**返回 null**

压缩 trie 事实上变成了一个「后缀 → 值」模式匹配器。对于从未见过的名字，作者用 Statistics Iceland 的真实分布数据估算：综合错误率约 0.34%，其中「完全错误的变格」只有 0.046%。

## 两个关键前提

- **规律性 (regularity)**：相似后缀确实映射到同一值。若数据无此特性，子树永远无法压缩。
- **全面性 (comprehensiveness)**：样本必须包含规则**与反例**。只有当 `Baldur`（编码 `"ur,ur,ri,urs"`）这样的反例出现时，`dur` 子树才不会被误压。3,600 样本覆盖 80% 名字，已足以捕获大多数规则加例外。

## 兄弟叶合并

再压榨一轮：兄弟叶若值相同，可合并为单节点，key 变成字符集合（如 `ibdfjklmnpstvxðóú`），lookup 时 `findChild` 改为「key 包含当前字符」即可。最终 trie 从 4.01 kB 降到 3.27 kB，又省 18%。

## 工程教训

作者反省：若今天重做，会把 `beygla/strict`（完整名单、10 kB 更多、100% 正确）作为默认，把这棵「会犯 0.34% 错」的压缩 trie 作为可选小型变体。在司法文书等场景，正确性远比体积重要——**「酷」不是交付标准**。

这套方法可迁移到其他有格变语言（斯拉夫语族、巴尔干语族）。
