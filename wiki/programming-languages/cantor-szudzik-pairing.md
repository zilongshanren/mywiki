# Cantor 与 Szudzik 配对函数

**配对函数（pairing function）**是把两个数映射为一个唯一整数的函数：`pair(x, y) = z`。它在着色器、地图系统、实例化渲染器等需要“用一对值构造唯一键”的场合随处可见。最经典的两种是 Cantor 配对和 Szudzik 配对，两者实现都是几行代码，但打包效率有明显区别。

## Cantor 配对

Cantor 配对最早来自集合论，用来证明自然数对与自然数一一对应。其公式为：

$$index = \frac{(x+y)(x+y+1)}{2} + y$$

几何上可以把它想象成在 2D 网格上按**对角线**依次编号：沿着 (0,0) → (1,0) → (0,1) → (2,0) → (1,1) → (0,2) 的锯齿路径遍历整张无穷大网格，每访问到一个格子就给它一个自增的 index。这种对角线枚举保证了任意两个非负整数对都会对应到唯一 index。

Cantor 的缺点是**打包效率偏低**。理想状态下，`pair(9,9)` 应当恰好等于 99（覆盖 0..9 × 0..9 共 100 组），然而 `cantor(9,9) = 200`，意味着前 100 个组合用掉了 200 个 index，利用率只有 50%。反映到边界上：`cantor(33000, 33000) ≈ 2.18 × 10^9`，这已经贴近 32 位有符号整数的上限；切换到无符号 32 位也只把安全输入略微抬高到 46500 左右。对于着色器或 `Map` key 这类 32 位紧张的场景，Cantor 很快就会遭遇溢出。

## Szudzik 配对

Szudzik 配对（Matthew Szudzik 提出）按**方框 L 形**而非对角线扫描 2D 网格：沿着 `max(x, y)` 的等值线一层一层往外扩。实现上只有两种分支：

- 若 `x >= y`：`index = x*x + x + y`
- 否则：`index = y*y + x`

几何含义是“先把边长为 `max(x,y)` 的方框内部填满，再填下一层”。因此它的打包效率接近完美——`szudzik(9,9) = 99`，100% 利用。对 32 位有符号返回值而言，Szudzik 能容纳的最大输入是 `⌊√(2^31 − 1)⌋ = 46340`；对 32 位无符号则是 65535。在相同位宽下，Szudzik 的可用输入空间几乎是 Cantor 的两倍。

## 负数输入的处理

两种配对函数原生都只接受非负整数。要支持负输入，通常先对 `x`、`y` 各做一次“Z 变换”：

$$b = \begin{cases} -2y - 1 & y < 0 \\ 2y & y \ge 0 \end{cases}$$

即把负数映射到奇数、非负数映射到偶数，再把变换后的结果喂给原始公式。注意所有返回 index 仍是非负整数，因此带负数后打包效率会折半左右。Szudzik 还有一种更节省空间的改写：根据 `(a, b)` 的符号组合决定输出是 `c` 还是 `-c - 1`，把一半结果挪到负轴上，以同一比特宽度再多装一倍数据。

## 性能

两个函数都是“几条算术指令”，在 jsperf 上几乎同等快速（Szudzik 略胜约 0.7%）。作者 [[steven-sell]] 报告的数据中，Cantor、Szudzik 及各自的 signed 变体都在 8.8–8.9 亿 ops/sec 区间。真正影响选型的不是 ops/sec，而是**数据范围和 key 空间紧密度**：

- 想最大化 32 位空间利用 → Szudzik；
- 打包效率影响不大、想要最小最干净的实现 → Cantor 也无妨；
- 需要频繁处理负坐标 → 考虑 Szudzik 的 signed 变体。

## 典型用途

- **Map 键**：在 [[performance-conscious-webgl]] 中，作者用 Cantor 把 `(material_id, mesh_id)` 打包成整数 key，替换原来的字符串 key 后 `Map` 插入从 17ms 降到 1ms。这是 [[cache-friendliness|缓存友好性]]和“避免运行时字符串哈希”两者叠加的效果。
- **无碰撞空间哈希**：只要能保证输入有界且不超过 Szudzik 极限，就能在不经碰撞的情况下给 2D 坐标生成唯一整数 id，适合用作稀疏数据结构的桶索引。
- **着色器内寻址**：在 fragment shader 中把像素坐标打包成一个 int，用于查表或程序纹理，相关手法参见 [[pcg3d-hash]] 和 [[non-cryptographic-hash]] 中讨论的替代方案。

与典型的 [[non-cryptographic-hash|非密码学散列]]不同，配对函数是**可逆且无碰撞**的双射——在输入域内每一对 `(x,y)` 恰好对应一个 index，也可以从 index 还原出原始的 `(x,y)`。这是它们作为“唯一 id 生成器”比哈希更严格的地方。
