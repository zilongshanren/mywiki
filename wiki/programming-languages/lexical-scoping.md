# 词法作用域（Lexical Scoping）

**变量的作用域由代码的静态结构决定**，而非运行时调用栈。

## 词法 vs 动态作用域

| | 词法作用域 | 动态作用域 |
|---|---|---|
| 作用域确定于 | 代码书写时 | 运行时调用栈 |
| 可静态分析 | 是 | 否 |
| 可读性 | 高 | 低 |
| 闭包天然支持 | 是 | 否 |

## 历史

**Scheme（1975）** 是 Lisp 家族中**第一个**默认使用词法作用域的变体——打破当时 Lisp 社区的动态作用域惯例。这个选择深刻影响了后来所有现代编程语言（JS、Python、Ruby、Rust 等全部词法作用域）。

## 为什么词法作用域赢了

- **可预测性**：只看代码就能确定变量来自哪里。
- **重构安全**：改函数调用顺序不会改变语义。
- **闭包的基础**：函数携带其定义环境一起旅行。

## 常见陷阱

JavaScript `var` 的函数作用域、ES6 `let`/`const` 的块作用域，是同一家族但粒度不同。Python 的 nonlocal/global 关键字是对词法作用域默认行为的局部覆盖。
