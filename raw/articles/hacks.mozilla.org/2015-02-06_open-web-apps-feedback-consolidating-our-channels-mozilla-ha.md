In August 2014 we [announced the opening of a new feedback channel for web apps](https://hacks.mozilla.org/2014/08/launching-open-web-apps-feedback-channels-help-us-make-the-web-better/) on UserVoice. It has led to some good discussions and here are a few highlights:

[This post](https://openwebapps.uservoice.com/forums/258478-open-web-apps/suggestions/6329093-enabling-the-file-system-api-on-all-systems-instea)showed the importance of the nascent[FileSystem API](http://w3c.github.io/filesystem-api).- A
[suggestion about background services](https://openwebapps.uservoice.com/forums/258478-open-web-apps/suggestions/6258744-background-service-for-apps)reinforced the need for something like the proposed[BackgroundSync API](https://github.com/slightlyoff/BackgroundSync/). This idea was implemented for Firefox OS as the slightly-different-but-similarly-named[requestSync API](https://bugzilla.mozilla.org/show_bug.cgi?id=1018320)as a stopgap until Firefox OS has a full[Service Worker](https://github.com/slightlyoff/ServiceWorker/)[implementation](https://bugzilla.mozilla.org/show_bug.cgi?id=1059784). [A good discussion about centrally managing disk usage](https://openwebapps.uservoice.com/forums/258478-open-web-apps/suggestions/6268041-a-quote-api-for-local-storage-and-indexeddb%20)ensured that something akin to the incipient[quota API](http://www.w3.org/TR/quota-api/)remained a priority for Mozilla’s Gecko developers.[A request for a new version of localStorage](https://openwebapps.uservoice.com/forums/258478-open-web-apps/suggestions/6323700-localstorage-2-asynchronous-and-object-ready%20)re-iterated the desire for a storage mechanism that has a lot of differing opinions but no single proposal at this time.

We would like to sincerely thank those who have provided input and participated in all of the discussions. Unfortunately, after some great initial levels of participation we have since seen usage fall, so at this time we think it is best to discontinue use of [openwebapps.uservoice.com](https://openwebapps.uservoice.com). With UserVoice’s handy data exporting services, we’ve made sure we have an archived copy of the ideas posted and interactions that took place on the site.

Please keep the feedback and feature suggestions coming. It’s essential for us to continue to hear from developers like you. We’d simply like to redirect feedback back to mailing lists/newsgroups (see [this list of IRC channels and mailing lists](https://wiki.mozilla.org/Apps#IRC_Chat_and_Mailing_Lists) for some Mozilla app-specific channels), [specifiction.org/](http://specifiction.org/) which aims to be a forum for building web standards, and Bugzilla instances like [Mozilla’s](http://bugzilla.mozilla.org/).

**Note**: The Firefox Developer Tools feedback channel hosted on UserVoice ([ffdevtools.uservoice.com](https://ffdevtools.uservoice.com/)) is very active and is most definitely remaining open!
