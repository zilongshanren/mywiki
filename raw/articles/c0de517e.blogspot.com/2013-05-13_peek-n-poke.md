Sometimes I write tools

[small](http://c0de517e.blogspot.ca/2011/07/little-tool-for-debugging-with.html)and[stupid](http://c0de517e.blogspot.ca/2010/12/stupid-sample-generator.html)enough to be contained in a blog post. This in one of them...
I always wanted to have graphical visualizers inside visual studio, to see matrices, points, images and such things from raw memory locations. It turns out that's very simple if you just ReadProcessMemory from an external tool, even simpler than writing a





[Visual Studio extension](http://docs.opencv.org/doc/tutorials/introduction/windows_visual_studio_image_watch/windows_visual_studio_image_watch.html). Of course, this doesn't work when remote debugging (and the simplest option there would be to write a server or just something[intrusive in the code](http://www.billbaxter.com/projects/imdebug/)).
This small C# sample does display images from a process memory, refreshing every 33ms, it supports a few formats (r8 is broken as I was too lazy to set the palette, expect bugs in general...) but it could be easily extended to do whatever you need (i.e. graph floats in time...).


Enjoy!
