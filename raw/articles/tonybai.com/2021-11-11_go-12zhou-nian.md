# Go，12周年

![](../../assets/81d7d34ded073c9e.png)


[本文永久链接](https://tonybai.com/2021/11/11/go-opensource-12-years) – https://tonybai.com/2021/11/11/go-opensource-12-years

2009年11月10日，Go语言正式对外发布并开源。如今，距那一历史时刻已经过去12年了。今早Go核心团队技术负责人[Russ Cox在Go官博撰文庆祝Go开源12周年](https://go.dev/blog/12years)，他回顾了这一年来发布的Go 1.16与Go 1.17版本给Go与Go社区带来的变化，粗略总结了Go核心团队的重点工作，并展望了2022年将发布的Go 1.18和Go 1.19版本。这里对Russ Cox的文章做了简单翻译，供大家参考。

### 回顾这一年

今天我们庆祝Go语言开源的12岁生日。今年我们经历了多事的一年，明年也有很多值得期待的事情。

与去年庆祝[Go 11岁生日的博文](https://tonybai.com/2020/11/11/go-opensource-11-years/)相比，这篇博客最明显的变化是它位于我们[在go.dev上的新家](https://go.dev/blog/tidy-web)，这是将我们所有的Go网站整合成一个统一的网站的一部分。整合的另一部分是[用pkg.go.dev取代godoc.org](https://go.dev/blog/godoc.org-redirect)。

今年2月，[Go 1.16版本](https://mp.weixin.qq.com/s/UPNn4G_m0zfvJgWxEVl_Tw)增加了[对macOS ARM64的支持](https://go.dev/blog/blog/ports)，增加了[文件系统接口](https://mp.weixin.qq.com/s/_pUtGQSl_oSRnmmfROJ6ZQ)和[嵌入文件特性](https://mp.weixin.qq.com/s/UPNn4G_m0zfvJgWxEVl_Tw)，并使得go module构建模式成为默认启用的机制，同时还进行了一系列的改进和优化。

今年8月，[Go 1.17版本](https://mp.weixin.qq.com/s/y_pC6GYeZnKuHG8ycNy6rg)增加了对Windows ARM64的支持，[使TLS密码套件的决策更加简单和安全](https://go.dev/blog/tls-cipher-suites)，引入了[修剪模块图](https://mp.weixin.qq.com/s/Fer90nattWxXDWDC1VV55w)，使module在大型项目中更加有效，并[增加了新的、更易读的构建约束语法(译注：go:build)](https://mp.weixin.qq.com/s/AkJoXLlpSmw5vMZDpXoq5w)。在系统内部，Go 1.17还为[x86-64上的Go函数切换到了基于寄存器的调用约定](https://mp.weixin.qq.com/s/AkJoXLlpSmw5vMZDpXoq5w)，使依赖CPU的计算密集型的应用程序的性能提高了5-15%。

在这一年中，[我们发布了许多新的教程](https://golang.google.cn/doc/tutorial/)，比如：[Go语言数据库操作指南](https://golang.google.cn/doc/database/)、[module开发指南](https://golang.google.cn/doc/#developing-modules)和[Go module参考手册](https://golang.google.cn/ref/mod)。其中一个亮点是新的教程[“用Go和Gin开发RESTful API”](https://golang.google.cn/doc/tutorial/web-service-gin)，该教程也可以[通过Google Cloud Shell以互动的形式获得](https://golang.org/s/cloud-shell-web-tutorial)。

我们在IDE方面一直很忙，我们在[VS Code Go中默认启用了gopls](https://go.dev/blog/gopls-vscode-go)，并对gopls和VS Code Go进行了无数次的改进，包括[由Delve提供的强大的调试体验](https://github.com/golang/vscode-go/blob/master/docs/debugging.md)。

我们还推出了[Go Fuzzing test公测版](https://go.dev/blog/fuzz-beta)，并[正式提议在Go中加入泛型](https://mp.weixin.qq.com/s/SMT40557JgQ9FjUkswznlA)，现在这两项都有望在Go 1.18中实现。

为了继续适应”虚拟优先(virtual-first)”，[Go团队在Google Open Source Live上举办了我们的第二个年度Go day](https://opensourcelive.withgoogle.com/events/go-day-2021)，你可以在YouTube上观看这些讲座。

- Ian Lance Taylor的
[“在Go中使用泛型”](https://mp.weixin.qq.com/s/ur1eiZl4PKbF1PqELAdfKg)，介绍了泛型以及如何有效地使用它们。 [“现代企业应用”](https://www.youtube.com/watch?v=5fgG1qZaV4w)，由Steve Francia主讲，展示了Go如何在企业现代化中发挥作用。- Suzy Mueller的i
[“用Go编辑器构建更好的项目”](https://www.youtube.com/watch?v=jMyzsp2E_0U)，展示了VS Code Go的集成工具如何帮助你浏览代码、调试测试等。 - 美国运通公司的杰出工程师Benjamin Cane的
[“从概念验证到生产”](https://www.youtube.com/watch?v=e7PtBOsTpXE)，解释了美国运通公司如何在其支付和奖励平台中使用Go。

### 向前迈进

我们对Go的第13年的发展感到非常兴奋。下个月，我们将在[GopherCon 2021](https://www.gophercon.com/)上举办两场讲座，同时[还有许多来自Go社区的天才演讲者](https://www.gophercon.com/agenda)。请免费注册，并在你的日历上做个记号。

- “
[为什么和如何使用Go泛型](https://www.gophercon.com/agenda/session/593015)“，由Robert Griesemer和Ian Lance Taylor主讲，他们领导了这项新功能的设计和实施。 12月8日，上午11:00（美国东部）。 [“使用调试适配器协议（DAP）调试Go代码”](https://www.gophercon.com/agenda/session/593029)，作者Suzy Mueller，展示如何使用VS Code Go的高级调试功能与Delve。

12月9日，下午3:20（美国东部时间）。

明年2月，Go 1.18版本将把[新的基于寄存器的调用约定](https://mp.weixin.qq.com/s/AkJoXLlpSmw5vMZDpXoq5w)扩展到非x86架构，并带来巨大的性能改进。它将包括新的Go fuzzing test支持。这将是第一个包括对泛型支持的版本。

泛型将是我们2022年的重点之一。[Go 1.18中的初始版本](https://mp.weixin.qq.com/s/_4p1wyo3eKEaCU_9GNdkLA)只是一个开始。我们需要花时间使用泛型，了解哪些是有效的，哪些是无效的，这样我们才能写出最佳实践，并决定哪些应该被添加到标准库和其他库中。我们期望Go 1.19（预计在2022年8月）及以后的版本将进一步完善泛型的设计和实现，以及将其进一步整合到整个Go体验中。

2022年的另一个重点是（Go包的）供应链安全。我们多年来一直在[讨论依赖性的问题](https://research.swtch.com/deps)。Go module的设计提供了[可重复、可验证、可核实的构建](https://research.swtch.com/vgo-repro)，但仍有更多工作要做。从Go 1.18开始，go命令将在二进制文件中嵌入更多关于其构建配置的信息，这既是为了使可重复性更容易，也是为了帮助那些需要为Go二进制文件生成[软件材料清单(Software Bill of Materials, SBOM)](https://en.wikipedia.org/wiki/Software_bill_of_materials)的项目。我们也已经开始了[Go漏洞数据库](https://pkg.go.dev/golang.org/x/vuln)和相关工具的工作，以报告程序依赖中的漏洞。我们在这项工作中的目标之一是大幅提高这种工具的信噪比：如果一个程序不使用有漏洞的函数，我们就不会报告。在2022年期间，我们计划将其作为一个独立的工具，并将其添加到现有的工具中，包括gopls和VS Code Go，以及pkg.go.dev中。还有更多工作要做，以改善Go的供应链安全态势的其他方面。请继续关注细节。

总的来说，我们预计2022年对Go来说也将是多事的一年，我们将继续提供你所期望的及时发布和改进。
